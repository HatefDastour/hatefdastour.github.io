7.5. Retrieval Strategies#

7.5.1. Learning objectives#

By the end of this section, you should be able to:

  • Implement top-k similarity search over a vector store and explain what k controls.

  • Explain how Maximal Marginal Relevance (MMR) trades relevance for diversity, and when that trade-off is worthwhile.

  • Explain the role of a re-ranking pass and why it can correct errors that embedding similarity alone misses.

  • Choose an appropriate retrieval strategy given a query’s breadth and the redundancy of the underlying corpus.

7.5.2. Similarity Search#

The most direct retrieval method embeds the query and returns the k chunks whose embeddings are closest by cosine similarity.

query = "What is RAG?"
results = chroma_db.similarity_search(query, k=2)

for i, doc in enumerate(results, start=1):
    print(f"Result {i}: {doc.page_content}")

Increasing k returns more chunks but risks introducing noise, since lower-ranked chunks are less relevant by construction. A value of 2–5 is typical for most RAG applications, and should be tuned against retrieval evaluation metrics rather than fixed a priori.

7.5.3. Maximal Marginal Relevance (MMR)#

Pure similarity search can return several chunks that are all near-duplicates of each other — relevant, but redundant. MMR re-ranks candidates to balance relevance against diversity, so the retrieved set covers more of the query’s information need.

MMR is especially valuable for broad queries that touch multiple sub-topics, where pure similarity search would otherwise surface several chunks saying the same thing.

7.5.4. Re-ranking Retrieved Chunks#

After an initial retrieval pass — typically over-fetching more candidates than will ultimately be used — a cross-encoder re-ranker scores each (query, chunk) pair jointly, rather than comparing independently-computed embeddings. This second pass is more expressive than embedding similarity and can catch relevant chunks that the initial pass under-ranked.

Show code cell source

Hide code cell source

 
from langchain_community.cross_encoders import HuggingFaceCrossEncoder

reranker = HuggingFaceCrossEncoder(model_name="cross-encoder/ms-marco-MiniLM-L-6-v2")

candidates = chroma_db.similarity_search(query, k=5)
pairs = [(query, doc.page_content) for doc in candidates]
scores = reranker.score(pairs)

ranked = sorted(zip(scores, candidates), key=lambda x: x[0], reverse=True)
for score, doc in ranked[:2]:
    print(f"Score: {score:.4f} | {doc.page_content}")

Score: 7.1133 | RAG stands for Retrieval-Augmented Generation. It grounds LLM outputs in external knowledge.
ChromaDB is a vector store optimized for storing and retrieving embeddings efficiently.

Note

Re-ranking adds latency but significantly improves precision. Use it when accuracy is more important than response time.

7.5.5. Exercises and discussion#

  1. Similarity vs. MMR Run the same broad query against both similarity_search and max_marginal_relevance_search on a corpus with several near-duplicate passages. Compare the retrieved sets. Under what query characteristics does MMR’s diversity gain outweigh its relevance cost?

  2. When re-ranking changes the answer Find a query where the top-1 result from plain similarity search differs from the top-1 result after cross-encoder re-ranking. Inspect both chunks — why might the embedding model have under-ranked the chunk that the cross-encoder preferred?

  3. Retrieval strategy selection Given a customer-support knowledge base with many overlapping FAQ entries and low latency tolerance, design a retrieval strategy (choice of k, whether to use MMR, whether to re-rank) and justify each choice.
