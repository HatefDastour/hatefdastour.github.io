7.2. Prompt Templates#

7.2.1. Learning objectives#

By the end of this section, you should be able to:

  • Explain the purpose of PromptTemplate and how it differs from hardcoded prompt strings.

  • Create PromptTemplate objects with named input variables and format them with concrete values.

  • Use ChatPromptTemplate for models that expect structured role-tagged messages.

  • Explain the advantages of templates over ad-hoc string formatting in terms of reusability, maintainability, and composability.

  • Compose a prompt template with an LLM to create a reusable, end-to-end callable unit.

7.2.2. Why Templates Matter#

In Chapter 6, prompts were constructed as Python f-strings — direct string interpolation with no structure beyond the string itself. This works for one-off experiments but breaks down in real applications:

Table 7.5 Comparison of Prompting Approaches#

Without Templates

With Templates

Ad-hoc string formatting

Structured, reusable components

Error-prone manual concatenation

Validated input variables

Hard to maintain when prompts change

Easy to update in one place

Not composable

Chainable with other LangChain components

No separation of instruction and data

Instruction and data explicitly separated

The key conceptual shift: a prompt template is a function that maps variable inputs to a complete prompt string. Treating it as a function — with named inputs and a clear specification — makes it testable, versionable, and reusable across multiple calls.

7.2.3. Basic PromptTemplate#

LangChain’s [Chase, 2022] PromptTemplate defines a prompt with named variables in curly braces:

Show code cell source

Hide code cell source

 
from langchain_core.prompts import PromptTemplate

template = PromptTemplate(
    input_variables=["topic", "level"],
    template=(
        "You are a helpful instructor.\n"
        "Explain {topic} in simple terms suitable for a {level} student.\n"
        "Use one concrete analogy."
    ),
)

# Format with concrete values
prompt_str = template.format(topic="gradient descent", level="high school")
print(prompt_str)

You are a helpful instructor.
Explain gradient descent in simple terms suitable for a high school student.
Use one concrete analogy.

The format method validates that all required variables are provided, raising a KeyError if any are missing. This validation catches prompt construction errors at development time rather than silently producing malformed prompts at runtime.

7.2.4. Composing a Template with an LLM#

LangChain’s pipe operator (|) composes a template and an LLM into a callable chain:

Show code cell source

Hide code cell source

 
from langchain_core.prompts import PromptTemplate
from langchain_community.llms import LlamaCpp

template = PromptTemplate(
    input_variables=["topic"],
    template="<|user|>\nExplain {topic} in one paragraph.<|end|>\n<|assistant|>\n",
)

llm = LlamaCpp(model_path="Phi-3-mini-4k-instruct-fp16.gguf", n_gpu_layers=-1, verbose=False)

# Compose template + LLM into a single callable
chain = template | llm

# Invoke: passes variables through template, then to LLM
response = chain.invoke({"topic": "attention mechanisms in transformers"})
print(response)

 Attention mechanisms in transformers are a crucial aspect of their architecture, enabling the model to dynamically weigh and selectively focus on different parts of input sequences during processing. In essence, an attention layer computes a weighted sum of all hidden states (representations) from each position in a sequence relative to every other position, allowing for context-aware representations by assigning importance to specific segments based on their relevance. This is achieved using queries, keys, and values extracted via self-attention or cross-attention mechanisms, where the output at any position effectively becomes a weighted combination of all input positions. As a result, transformers can capture long-range dependencies efficiently, making them highly effective for tasks such as language modeling, translation, and text classification.

The pipe operator creates a RunnableSequence: calling chain.invoke(inputs) formats the template with inputs, passes the result to the LLM, and returns the LLM’s output. This is the fundamental pattern for all LangChain pipelines.

7.2.5. ChatPromptTemplate#

For models that expect structured role-tagged messages (the chat template format from Chapter 6), use ChatPromptTemplate:

Show code cell source

Hide code cell source

 
from langchain_core.prompts import ChatPromptTemplate

chat_template = ChatPromptTemplate.from_messages([
    ("system", "You are a {role}. Respond in a {tone} tone."),
    ("human", "{question}"),
])

formatted = chat_template.format_messages(
    role="data science tutor",
    tone="friendly and encouraging",
    question="What is overfitting and how do I prevent it?",
)

for message in formatted:
    print(f"[{message.type}] {message.content}")

[system] You are a data science tutor. Respond in a friendly and encouraging tone.
[human] What is overfitting and how do I prevent it?

ChatPromptTemplate integrates with ChatOpenAI, ChatAnthropic, and other chat-style LLM backends that accept structured message lists rather than a single formatted string.

7.2.6. Partial Prompt Templates#

When some template variables are known in advance (e.g., a fixed system role), they can be partially filled using .partial(), creating a reusable template that only requires the remaining variables at call time:

Show code cell source

Hide code cell source

 
base_template = PromptTemplate(
    input_variables=["role", "task", "context"],
    template=(
        "You are {role}.\n"
        "Task: {task}\n"
        "Context: {context}"
    ),
)

# Partially fill the role — reuse this across many tasks
tutor_template = base_template.partial(
    role="a patient university-level NLP tutor")

# Later, provide only the remaining variables
prompt1 = tutor_template.format(
    task="Explain what attention is",
    context="The student has just finished reading about RNNs",
)
prompt2 = tutor_template.format(
    task="Explain the difference between BERT and GPT",
    context="The student understands the transformer architecture",
)

Partial templates reduce repetition: the system persona is defined once, and the task-specific variables are provided at each call site.

# Generate explanations for all topics using the same template

for topic, response in zip(topics, responses):

7.2.8. Exercises and discussion#

  1. Template design exercise Create a PromptTemplate for a code review assistant that takes three variables: language (programming language), code (the code to review), and focus (e.g., “security”, “performance”, “readability”). Format it for two different use cases and verify that the output structure is correct.

  2. Partial template comparison Build a template that has four variables: persona, expertise_level, topic, and format. Create three partial templates with different persona settings (e.g., teacher, journalist, engineer). For the same topic and format, compare how the three partial templates produce different outputs.

  3. Template vs. f-string reliability Write the same prompt using (a) a raw f-string and (b) a PromptTemplate. Deliberately omit a required variable in each case. What happens? Which approach gives a clearer error? Why does this matter in a production pipeline?
