8.3.6. LangChain Agent Framework#

8.3.6.1. Learning objectives#

By the end of this section, you should be able to:

  • Rebuild a ReAct agent using LangChain’s create_react_agent and AgentExecutor.

  • Explain what each LangChain component adds over the from-scratch implementation.

  • Define custom tools using the @tool decorator and explain how LangChain uses the docstring for tool description.

  • Configure AgentExecutor parameters: max_iterations, handle_parsing_errors, and verbose.

  • Use LangChain’s callback system to log and monitor agent execution.

8.3.6.3. Defining Tools with the @tool Decorator#

LangChain’s @tool decorator converts a Python function into a Tool object, using the function’s name and docstring automatically:

Show code cell source

Hide code cell source

 
from langchain.tools import tool

@tool
def web_search(query: str) -> str:
    """Mock web search function for offline sandbox environment."""
    query_lower = query.lower()
    if "macbook pro" in query_lower and "2026" in query_lower:
        return "The current price of a MacBook Pro 14-inch in 2026 is approximately $1,599 USD."
    return f"Search result for '{query}': No live results found in sandbox."


@tool
def python_calculator(expression: str) -> str:
    """
    Evaluate a Python arithmetic expression.
    Use for: arithmetic, percentages, unit conversions.
    Input: a Python expression (e.g., '1999 * 0.85').
    Output: the computed result.
    """
    import math
    try:
        result = eval(expression, {"__builtins__": {}, "math": math})
        return str(round(float(result), 6))
    except ZeroDivisionError:
        return "Error: division by zero"
    except Exception as e:
        return f"Error: {str(e)}"


tools = [web_search, python_calculator]

The @tool decorator extracts:

  • tool.name — the function name

  • tool.description — the docstring (used in the agent’s system prompt)

  • tool.args_schema — inferred from type annotations

A well-written docstring is as important here as in the custom registry — the model reads it to decide when to use the tool.

8.3.6.4. Building and Running the LangChain Agent#

Show code cell source

Hide code cell source

 
from langchain_classic.agents import create_react_agent, AgentExecutor
from langchain_core.prompts import PromptTemplate
from langchain_community.llms.llamacpp import LlamaCpp

# Initialize the local LLM model instance
llm = LlamaCpp(
    model_path="./Phi-3-mini-4k-instruct-fp16.gguf",
    n_ctx=2048,
    n_gpu_layers=-1,
    temperature=0.0,
    max_tokens=300,
    verbose=False,
)

# Define the standard ReAct prompt locally to work completely offline
template = """Answer the following questions as best you can. You have access to the following tools:

{tools}

Use the following format:

Question: the input question you must answer
Thought: you should always think about what to do
Action: the action to take, should be one of [{tool_names}]
Action Input: the input to the action
Observation: the result of the action
... (this Thought/Action/Action Input/Observation can repeat N times)
Thought: I now know the final answer
Final Answer: the final answer to the original input question

Begin!

Question: {input}
Thought:{agent_scratchpad}"""

prompt = PromptTemplate.from_template(template)

# Create the agent
agent = create_react_agent(llm=llm, tools=tools, prompt=prompt)

# Wrap in an executor
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,
    max_iterations=6,
    handle_parsing_errors=True,
    return_intermediate_steps=True,
)

result = agent_executor.invoke({
    "input": (
        "Find the current price of a MacBook Pro 14-inch in USD in 2026. "
        "Then calculate its price in euros using an exchange rate of 0.89."
    )
})

print("\n=== Final Answer ===")
print(result["output"])

8.3.6.5. Key AgentExecutor Parameters#

Parameter

Default

Effect

max_iterations

15

Maximum number of action steps before forced termination

handle_parsing_errors

False

If True, recovers from malformed output and re-prompts

verbose

False

Prints the full reasoning trace to stdout

return_intermediate_steps

False

Returns (action, observation) pairs alongside the final output

early_stopping_method

“force”

What to do when max_iterations is reached: “force” returns last output

handle_parsing_errors=True is strongly recommended for production agents — it prevents a single malformed model output from crashing the entire agent loop. When the parser fails, LangChain appends an error message to the context and asks the model to reformat its output.

8.3.6.6. Callbacks: Monitoring Agent Execution#

LangChain’s callback system allows logging, monitoring, and tracing without modifying agent code:

Show code cell source

Hide code cell source

 
from langchain.callbacks import StdOutCallbackHandler
from langchain.callbacks.base import BaseCallbackHandler

class CustomAgentLogger(BaseCallbackHandler):
    """Custom callback for logging agent actions."""

    def on_agent_action(self, action, **kwargs):
        print(f"[ACTION] Tool: {action.tool} | Input: {action.tool_input}")

    def on_tool_end(self, output, **kwargs):
        print(f"[OBSERVATION] {str(output)[:200]}")

    def on_agent_finish(self, finish, **kwargs):
        print(f"[FINISHED] {finish.return_values.get('output', '')[:300]}")


# Attach callback to the executor
agent_executor_with_logging = AgentExecutor(
    agent=agent,
    tools=tools,
    callbacks=[CustomAgentLogger()],
    max_iterations=6,
    handle_parsing_errors=True,
)

Callbacks enable production monitoring without modifying the agent’s core logic. Common uses include: logging to a database, sending alerts on tool failure, tracking token usage, and building debugging dashboards.

8.3.6.7. Comparing From-Scratch vs. LangChain#

Having implemented both, the key lessons are:

  • Complete visibility into all behavior

  • No external dependencies for the core loop

  • Easy to customize the exact prompt format

  • Manual error recovery

  • No streaming or async support

  • No standardized callback/monitoring interface

  • Robust parsing with automatic error recovery

  • Streaming, async, batch support built-in

  • Standardized callback and monitoring interface

  • Rich ecosystem (memory, tools, vector stores)

  • Additional dependency complexity

  • Abstractions can hide important behaviors

  • Framework changes can break agent behavior between versions

The recommended workflow: build from scratch first to understand what is happening, then migrate to LangChain for production deployments where robustness and ecosystem integration matter.

8.3.6.8. Exercises and discussion#

  1. Framework vs. scratch comparison Run the same three questions through both your from-scratch agent (Section 9) and the LangChain agent. Compare: success rate, number of steps taken, error recovery behavior, and output quality. What failure modes does handle_parsing_errors=True recover from that your from-scratch agent would crash on?

  2. Custom callback implementation Implement a callback that counts the total number of tool calls across a session and records which tool is called most frequently. Run 10 different questions through the agent and print the tool usage statistics. What does the distribution reveal about which tools are most valuable for the tested question types?

  3. Prompt template customization Pull the hwchase17/react prompt and print it. Identify three components of the template. Now create a custom PromptTemplate that modifies the output format — for example, requiring the model to rate its confidence (1–5) in its Thought before each Action. Test whether the modified template improves or degrades agent performance on five questions.
