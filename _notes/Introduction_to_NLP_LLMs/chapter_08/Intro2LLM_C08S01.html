8.3.1. Agents and the ReAct Framework#

8.3.1.1. Learning objectives#

By the end of this section, you should be able to:

  • Define an agent and explain how it differs from a passive LLM and from a fixed chain.

  • Describe the ReAct (Reason + Act) pattern and trace a complete agent reasoning loop.

  • Equip a LangChain agent with tools and explain how the model selects which tool to call.

  • Run a LangChain ReAct agent on a multi-step question and interpret the reasoning trace.

  • Explain when agents are appropriate and when chains or single LLM calls are preferable.

8.3.1.2. What Is an Agent?#

All models in previous sections were passive: they received a prompt and returned a response. A fixed chain adds sequencing but still follows a predetermined path. An agent breaks this pattern entirely:

8.3.1.3. The ReAct Framework#

Agents in LangChain [Chase, 2022] commonly follow the ReAct (Reasoning + Acting) pattern, introduced by Yao et al. [Yao et al., 2023]. The model alternates between explicit reasoning and tool-use actions:

The ReAct format works because:

  1. Thought generates an explicit reasoning step before each action — reducing errors from impulsive tool use.

  2. Action + Action Input are parseable tokens that can be detected programmatically to trigger tool calls.

  3. Observation inserts the tool result back into the model’s context, enabling it to reason about real-world information.

  4. The loop repeats until the model generates “Final Answer” — signaling task completion.

8.3.1.4. Equipping an Agent with Tools#

LangChain provides built-in tools for common operations and a Tool class for custom functions:

# Imports adapted for langchain_classic. In LangChain 1.0+ (2026), the
# legacy AgentExecutor / create_react_agent loop moved to the `langchain-classic`
# package; the new default entry point for agents is `create_agent` in
# `langchain.agents`, built on LangGraph. We use the classic loop here on
# purpose: it exposes the raw Thought / Action / Observation text protocol,
# which is the whole point of this section. See the note below the next
# code cell for when you'd reach for `create_agent` instead.
from langchain_classic.agents import AgentExecutor, create_react_agent
from langchain_classic.tools import Tool

# NOTE: DuckDuckGoSearchRun depends on the `ddgs` package. Its older
# dependency, `duckduckgo_search`, was renamed to `ddgs` in 2025 — if you
# hit an import or runtime error here, run `pip install -U ddgs`.
from langchain_community.tools import DuckDuckGoSearchRun

import ast
import operator as op

# Built-in search tool
search = DuckDuckGoSearchRun()

# --- Calculator tool ---------------------------------------------------
# We deliberately avoid Python's eval(): the expression it evaluates is
# text generated by the model, and eval() will execute *any* Python code
# it's handed (e.g. "__import__('os').system('...')"), not just arithmetic.
# This restricted evaluator walks the parsed expression tree and only
# allows numeric literals and basic arithmetic operators.
_OPS = {
    ast.Add: op.add, ast.Sub: op.sub, ast.Mult: op.mul,
    ast.Div: op.truediv, ast.Pow: op.pow, ast.USub: op.neg,
    ast.Mod: op.mod, ast.FloorDiv: op.floordiv,
}

def _eval_node(node):
    if isinstance(node, ast.Constant) and isinstance(node.value, (int, float)):
        return node.value
    if isinstance(node, ast.BinOp) and type(node.op) in _OPS:
        return _OPS[type(node.op)](_eval_node(node.left), _eval_node(node.right))
    if isinstance(node, ast.UnaryOp) and type(node.op) in _OPS:
        return _OPS[type(node.op)](_eval_node(node.operand))
    raise ValueError(f"unsupported expression: {ast.dump(node)}")

def calculator(expression: str) -> str:
    try:
        tree = ast.parse(expression, mode="eval")
        return str(_eval_node(tree.body))
    except Exception as e:
        return f"Error: {e}"

tools = [
    Tool(
        name="Search",
        func=search.run,
        description=(
            "Useful for searching the web for current information. "
            "Input should be a concise search query."
        ),
    ),
    Tool(
        name="Calculator",
        func=calculator,
        description=(
            "Useful for arithmetic calculations. "
            "Input should be a Python arithmetic expression (e.g., '2249 * 0.85')."
        ),
    ),
]

The description field is critical: the model reads tool descriptions to decide which tool to call. Clear, precise descriptions reduce the rate of incorrect tool selection.

8.3.1.5. Building and Running the Agent#

Show code cell source

from langchain_core.prompts import PromptTemplate 
from langchain_huggingface import HuggingFacePipeline 
from transformers import AutoModelForCausalLM, AutoTokenizer, pipeline 
import torch 

# Kept consistent with the instruct model used elsewhere in this course.
model_id = "Qwen/Qwen2.5-7B-Instruct" 
tokenizer = AutoTokenizer.from_pretrained(model_id, use_fast=True) 
model = AutoModelForCausalLM.from_pretrained(
    model_id, 
    dtype=torch.bfloat16,  # ~half the memory of default fp32; needs a GPU 
    device_map="auto", 
) 

pipe = pipeline(
    "text-generation", 
    model=model, 
    tokenizer=tokenizer, 
    max_new_tokens=512, 
    temperature=0.1, 
    return_full_text=False,  # only return the newly generated text 
) 

llm = HuggingFacePipeline(pipeline=pipe) 

react_template = """When searching for product prices, always query for the latest current-year model (e.g., current year 2026 / latest generation model) unless specified otherwise.

{tools}

Use the following format:

Question: the input question you must answer
Thought: you should always think about what to do
Action: the action to take, should be one of [{tool_names}]
Action Input: the input to the action
Observation: the result of the action
... (this Thought/Action/Action Input/Observation can repeat N times)
Thought: I now know the final answer
Final Answer: the final answer to the original input question

Question: {input}
{agent_scratchpad}"""

prompt = PromptTemplate.from_template(react_template) 

# Create the agent
agent = create_react_agent(
    llm=llm, 
    tools=tools, 
    prompt=prompt, 
) 

# Wrap in an executor that handles the action-observation loop
agent_executor = AgentExecutor(
    agent=agent, 
    tools=tools, 
    verbose=True, 
    max_iterations=5, 
    handle_parsing_errors="Check your output format! Ensure you respond with EITHER an Action/Action Input pair OR a Final Answer, never both.", 
) 

# Run on a multi-step question using the updated exchange rate (0.89)
result = agent_executor.invoke(
    {"input": "What is the current starting price of a 2026 MacBook Pro M5 base model in USD? Convert it to EUR using an exchange rate of 0.89."}
)

print(result["output"])

The reasoning trace shows the agent’s step-by-step decision making — which tool to use, what to pass to it, and how to interpret the result. This transparency is one of ReAct’s major advantages over black-box tool use.

Note on Output Parsing

In the trace above, the LLM generated both a tool action and a final answer in a single step, triggering LangChain’s handle_parsing_errors recovery mechanism. The agent executor corrected the format formatting on the fallback turn to produce the final result.

Agents are more powerful but less predictable. The model’s reasoning trace is not guaranteed to be correct — it can make wrong tool selections, misinterpret observations, or loop indefinitely without a max_iterations guard. For production use, agents require careful safeguards (covered in Section 12).

The practical rule: use chains when the task structure is known in advance; use agents when the task requires dynamic reasoning about intermediate results.

8.3.1.7. Exercises and discussion#

  1. Tool description sensitivity Build a two-tool agent (search and calculator). Write a deliberately vague description for the calculator tool (e.g., “does math things”). Observe whether the agent selects the correct tool for five different questions. Now rewrite the description to be precise. How does description quality affect tool selection accuracy?

  2. Max iterations impact Run the same complex question (requiring 3–4 tool calls) with max_iterations set to 2, 3, and 5. What happens when the iteration limit is reached before the agent has a final answer? Does the agent produce a partial answer or fail silently?

  3. Reasoning trace analysis Run five different questions through the agent with verbose=True. For each, identify: the number of reasoning steps, whether any step contained incorrect reasoning, and whether the final answer was correct. What fraction of intermediate “Thought” steps contain reasoning errors that are corrected in subsequent steps?
