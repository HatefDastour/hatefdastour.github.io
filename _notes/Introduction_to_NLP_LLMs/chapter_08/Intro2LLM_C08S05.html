8.5. Building a ReAct Agent from Scratch#

8.5.1. Learning objectives#

By the end of this section, you should be able to:

  • Describe the three components of a from-scratch ReAct agent: prompt template, action parser, and agent loop.

  • Implement a ReAct prompt template that provides the model with tool descriptions and the correct output format.

  • Implement a tool-call parser that extracts Action and Action Input fields from model output.

  • Implement the complete ReAct agent loop: generate → parse → execute tool → append observation → repeat.

  • Explain what agent frameworks (LangChain) abstract away and why building from scratch first is valuable.

8.5.2. Why Build from Scratch?#

LangChain’s [Chase, 2022] create_react_agent and AgentExecutor abstract away the implementation details of the ReAct [Yao et al., 2023] loop. Before using a framework, it is essential to understand what it is doing — because framework abstractions hide important design decisions and make debugging significantly harder.

Building a ReAct agent from scratch in ~120 lines of Python reveals every component:

  1. The prompt template — exactly what instructions the model receives

  2. The action parser — how tool calls are extracted from model output

  3. The agent loop — how observations are fed back into the context

Understanding these components makes it possible to debug agent failures, extend agent behavior, and reason about where things can go wrong.

8.5.3. The ReAct Prompt Template#

The prompt template instructs the model to follow the Thought → Action → Action Input → Observation format:

Hide code cell source

 
REACT_TEMPLATE = """You are a helpful AI assistant with access to the following tools:

{tool_descriptions}

Use the following format exactly:

Thought: [think about what to do]
Action: [tool name — must be one of: {tool_names}]
Action Input: [the input to pass to the tool]
Observation: [the tool's result — you will receive this]
... (repeat Thought/Action/Observation as needed)
Thought: I now have enough information to answer.
Final Answer: [your complete response to the user]

Begin!

User goal: {goal}

{scratchpad}"""


def build_prompt(goal: str, tool_registry, scratchpad: str = "") -> str:
    """Format the ReAct prompt with current goal and scratchpad."""
    tool_descriptions = "\n".join(
        f"- {name}: {info['description']}"
        for name, info in tool_registry.tools.items()
    )
    tool_names = ", ".join(tool_registry.tools.keys())
    return REACT_TEMPLATE.format(
        tool_descriptions=tool_descriptions,
        tool_names=tool_names,
        goal=goal,
        scratchpad=scratchpad,
    )

The scratchpad accumulates the Thought/Action/Observation trace from prior steps, giving the model a complete history of what it has already done.

8.5.4. The Action Parser#

The action parser extracts the Action and Action Input lines from the model’s output using regular expressions:

Show code cell source

Hide code cell source

 
import re

def parse_action(model_output: str) -> tuple[str | None, str | None, bool]:
    """
    Parse an action or final answer from model output.
    Returns: (action_name, action_input, is_final_answer)
    """
    # Check for final answer. Greedy (not lazy) and DOTALL: a Final Answer is the last
    # field in the output, so we want everything to the end, including line breaks.
    final_match = re.search(r"Final Answer:\s*(.+)", model_output, re.DOTALL)
    if final_match:
        return None, final_match.group(1).strip(), True

    # Extract action name
    action_match = re.search(r"Action:\s*(.+?)(?:\n|$)", model_output)
    if not action_match:
        return None, None, False

    # Extract action input. Stop at the next recognized field header (or end of string),
    # not just the next newline -- a lazy `(.+?)(?:\n|$)` would still truncate at the first
    # line break even with re.DOTALL set, since DOTALL only changes what `.` can match, not
    # where the lazy quantifier stops looking. This lookahead is what actually makes
    # multi-line action inputs work.
    input_match = re.search(
        r"Action Input:\s*(.+?)(?=\n(?:Thought:|Action:|Observation:|Final Answer:)|\Z)",
        model_output, re.DOTALL,
    )
    if not input_match:
        return None, None, False

    action = action_match.group(1).strip()
    action_input = input_match.group(1).strip()
    return action, action_input, False

A robust parser should handle common formatting variations the model might produce: extra whitespace, different capitalization, markdown formatting around the action name. Note that re.DOTALL alone is not enough for multi-line action inputs – it only lets . match newlines, but a lazy (.+?) will still stop at the very first one it finds. Bounding the match with a lookahead for the next field header (or end of string) is what actually captures multi-line input correctly.

8.5.5. The ReAct Agent Loop#

The complete agent loop ties together the prompt, model, parser, and tool registry:

Show code cell source

Hide code cell source

 
def run_react_agent(
    goal: str,
    llm,
    tool_registry,
    memory: AgentMemory = None,
    max_steps: int = 8,
    verbose: bool = True,
) -> str:
    """
    Run the complete ReAct agent loop.
    Returns the final answer string.
    """
    scratchpad = ""

    for step in range(max_steps):
        # Build the prompt with current scratchpad
        context = memory.build_context(goal) if memory else ""
        prompt = (
            f"<|user|>\n"
            f"{build_prompt(goal, tool_registry, scratchpad)}"
            f"{'Memory context:' + context if context else ''}"
            f"<|end|>\n<|assistant|>\n"
        )

        # FIX: Use llm.invoke() instead of calling llm() directly
        output = llm.invoke(prompt, stop=["\nObservation:", "\nObservation"])

        if verbose:
            print(f"\n[Step {step + 1}]\n{output.strip()}")

        # Parse the output
        action, action_input, is_final = parse_action(output)

        # Final answer — we're done
        if is_final:
            if verbose:
                print(f"\n[Final Answer]\n{action_input}")
            return action_input

        # No parseable action — model produced malformed output
        if action is None:
            observation = "Error: could not parse action. Use exactly: Action: [tool]\nAction Input: [input]"
        else:
            # Execute the tool
            observation = tool_registry.call(action, action_input)
            if verbose:
                print(f"[Observation] {observation}")

        # Append to scratchpad
        step_text = output.strip()
        scratchpad += f"\n{step_text}\nObservation: {observation}\n"

        # Update working memory
        if memory:
            memory.working.add("observation", f"Step {step + 1}: {observation}")

    return "Agent reached maximum steps without a final answer."

8.5.8. Exercises and discussion#

  1. Parser robustness Generate model outputs with deliberate formatting variations: extra spaces around “Action:”, lowercase “action input:”, multi-line action inputs, and missing “Action Input:” line. Test which variations your parse_action function handles correctly and which cause it to return (None, None, False). Extend the parser to handle at least two additional failure modes.

  2. Loop failure analysis Run the agent on five different questions with max_steps=3 (too few). Observe how the agent handles the step limit being reached: does it produce a partial answer, repeat itself, or terminate gracefully? Modify the loop to produce a best-effort answer from the scratchpad when the step limit is reached.

  3. Scratchpad ablation Implement a version of the agent loop that clears the scratchpad after each step (passing only the last observation). Run the same three-step question with and without the full scratchpad. How much does the full scratchpad improve performance compared to the step-by-step version? What does this reveal about the role of accumulated context in ReAct reasoning?
