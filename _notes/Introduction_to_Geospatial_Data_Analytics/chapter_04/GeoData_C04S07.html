4.7. Vector–Raster Integration#

4.7.1. Learning objectives#

By the end of this section, you should be able to:

  • describe a raster as a grid defined by a CRS, a transform, bands, and a no-data value;

  • check that vector and raster inputs are aligned before extracting values;

  • extract zonal statistics for polygons and explain which cells each rule includes;

  • handle no-data cells, small polygons, and polygons outside the raster;

  • choose summaries and resampling methods that fit continuous and categorical data;

  • sample a raster along a line; and

  • validate extracted values with coverage and sensitivity checks.

Section goal

Combine polygons and lines with raster surfaces without losing track of the grid. A small synthetic raster with known values shows what every extraction rule does before the same steps run on a repository raster.

Vector features describe discrete objects; rasters describe values on a regular grid. Combining them is useful for questions such as:

  • What is the mean NDVI [Tucker, 1979] inside each park?

  • Which buildings overlap high flood depth?

  • What is the elevation along a proposed route?

The answer depends on alignment, resolution, no-data handling, and the unit of analysis. A raster value without its grid definition and CRS is not interpretable.

4.7.2. What defines a raster#

A raster is a rectangular grid of cells. Each cell stores one value per band, and the cell represents an area, not a point: a 100 m cell holds one number for 10,000 m². The grid is placed on the Earth by a transform, which gives the coordinates of the top-left corner and the cell size, together with a CRS. Whether a statistic makes sense depends on what the values mean: a continuous raster (elevation, NDVI, temperature) supports means and other numeric summaries, whereas a categorical raster (land cover) stores class codes that must be counted instead. Table 4.26 lists the properties to read before any integration.

Table 4.26 Raster properties and the integration check that each one needs.#

Property

What it defines

The coordinate system of the grid

The meaning of a value is metadata, not something to guess. Satellite products often store scaled integers, such as a vegetation index multiplied by 10,000, so the metadata decides whether a stored 6,500 means 0.65. The same applies to the no-data code, which is a number like any other until it is masked.

4.7.3. Align the inputs#

Before extracting values, compare:

  1. CRS;

  2. bounds and overlap;

  3. pixel size and raster resolution;

  4. band data type and meaning; and

  5. no-data value and mask.

Reproject the vector features to the raster CRS. Reprojecting vectors only moves vertices, whereas reprojecting a raster resamples its values, so the vector is the layer to move. The cells below build a synthetic raster with known values: a 10 by 10 grid of 100 m cells in a UTM CRS, with values that rise toward the east and a 2 by 2 block of no-data cells standing in for cloud.

X0, Y0 = 705500, 5659000        # south-west corner of the toy raster (UTM zone 11N, metres)
NODATA = -9999.0
_keep_alive = []                # in-memory files must outlive the datasets opened from them


def open_raster(array, cell_size, nodata=NODATA, crs='EPSG:32611'):
    # Return an open in-memory GeoTIFF, so the example needs no file on disk.
    rows, cols = array.shape
    memfile = MemoryFile()
    with memfile.open(
        driver='GTiff', height=rows, width=cols, count=1, dtype=array.dtype, crs=crs,
        transform=from_origin(X0, Y0 + rows * cell_size, cell_size, cell_size), nodata=nodata,
    ) as dst:
        dst.write(array, 1)
    _keep_alive.append(memfile)
    return memfile.open()


row_index, col_index = np.mgrid[0:10, 0:10]
ndvi = (0.2 + 0.06 * col_index + 0.01 * row_index).astype('float32')   # rises toward the east
ndvi[2:4, 6:8] = NODATA                                                # a block of no-data cells
src = open_raster(ndvi, 100)


def describe_raster(src):
    return {
        'crs': src.crs.to_string(),
        'bounds': tuple(src.bounds),
        'pixel size (m)': src.res,
        'shape (rows, cols)': (src.height, src.width),
        'bands': src.count,
        'dtype': src.dtypes[0],
        'nodata': src.nodata,
    }


for key, value in describe_raster(src).items():

def local_box(x0, y0, x1, y1):
    # A box given in metres from the raster's south-west corner.
    return box(X0 + x0, Y0 + y0, X0 + x1, Y0 + y1)

4.7.4. Extract values for each polygon#

Extracting values for a polygon means choosing which cells belong to it, and Table 4.27 lists the common rules. mask implements the first two. With crop=True it returns only the window around the polygon, and with filled=False it returns a masked array, so cells outside the polygon and no-data cells are masked instead of being replaced by a number. count() on that array is then the number of valid cells.

Table 4.27 Rules for deciding which raster cells belong to a polygon.#

Rule

A cell is included when

mask option

Effect

Centre inside

Its centre lies inside the polygon

all_touched=False (default)

A small polygon can include no cell

Any contact

The polygon touches any part of the cell

all_touched=True

Every polygon gets a cell, but edges are over-weighted

Area-weighted

Weighted by the fraction of the cell inside

Not in mask; zonal-statistics tools such as exactextract

Most faithful, and heavier to compute

Two failures follow from these rules. A polygon smaller than a cell may contain no cell centre, so it has zero valid cells, and a polygon that lies completely outside the raster makes mask raise an error. The function below guards against both and reports them instead of stopping.

Hide code cell source

 
def summarize(src, polygons, all_touched=False):
    # Zonal mean and valid-cell count for each polygon, keyed by the index.
    if src.closed:
        raise ValueError(
            "The raster dataset is closed. Reopen it before calling summarize()."
        )

    raster_box = box(*src.bounds)
    records = []

    for feature_id, geometry in polygons.geometry.items():
        if not geometry.intersects(raster_box):
            records.append({
                "feature_id": feature_id,
                "valid_cells": 0,
                "mean_value": None,
                "note": "outside raster",
            })
            continue

        values, _ = mask(
            src,
            [geometry],
            crop=True,
            filled=False,
            all_touched=all_touched,
        )

        band = values[0]
        valid = int(band.count())

        records.append({
            "feature_id": feature_id,
            "valid_cells": valid,
            "mean_value": float(band.mean()) if valid else None,
            "note": "" if valid else "no valid cell",
        })

    return pd.DataFrame(records)

from rasterio.mask import mask

records = []

    if raster_crs is None:

            minimum = float(band.min())
            maximum = float(band.max())
        else:
            mean_value = minimum = maximum = None
        records.append(

4.7.5. Categorical and continuous rasters#

For a categorical land-cover raster, a mean is usually meaningless. Report class counts or proportions instead. In the toy land-cover raster below, classes 1, 2, and 3 stand for grass, trees, and water, and one polygon spans all three.

Show code cell source

Hide code cell source

 
landcover = np.ones((10, 10), dtype='int16')
landcover[:, 5:] = 2          # trees in the east
landcover[6:, :] = 3          # water in the south
cover_src = open_raster(landcover, 100, nodata=0)

values, _ = mask(cover_src, [local_box(310, 310, 690, 690)], crop=True, filled=False)
cells_in_polygon = values[0].compressed()

print('mean class (meaningless):', round(float(cells_in_polygon.mean()), 3))
classes, counts = np.unique(cells_in_polygon, return_counts=True)
for cls, count in zip(classes, counts):
    print(f'class {cls}: {count} cells, {count / len(cells_in_polygon):.1%}')

The mean of 1.875 describes no land-cover class, whereas the proportions say what is actually there.

Use nearest-neighbor resampling when a new grid must be created from a categorical raster. For a continuous surface, bilinear or cubic resampling can be appropriate, but the choice should be recorded. Table 4.28 lists the common methods.

Resolution also changes what a polygon sees, even without resampling choices. The cell below aggregates the toy NDVI raster to 200 m cells, ignoring no-data, and extracts the same polygons from both grids.

# Recreate the synthetic 100 m raster.
fine_src = open_raster(ndvi, 100)
by_park = parks.to_crs(fine_src.crs).set_index("park")

# Aggregate 2 × 2 blocks into 200 m cells, ignoring no-data.

    valid_count > 0,
    np.where(is_valid_cell, blocks, 0).sum(axis=2)
    / np.maximum(valid_count, 1),
    NODATA,
).astype("float32")

4.7.7. Measurement choices affect the result#

Small polygons may contain no complete pixels. Edge cells may be partly covered. Different raster resolutions can produce different summaries for the same polygon. Declare whether you:

  • include cells whose centers fall inside the geometry;

  • weight edge cells by covered area;

  • exclude or impute no-data cells;

  • summarize one band or several bands; and

  • treat each polygon, pixel, or date as the unit of analysis.

Never replace no-data with zero without checking the source metadata. Zero can be a valid observation, while no-data means that the observation is unavailable.

4.7.8. Quality checks#

Besides the structural checks, a coverage ratio shows how well the raster represents each polygon: the area of its valid cells divided by the polygon’s area. A ratio near 1 is reassuring. A ratio of 0 means that nothing could be extracted, a low ratio means that no-data or small size starved the statistic, and a ratio well above 1 means that the polygon is smaller than the cells counted for it.

4.7.9. Sampling a raster along a line#

A route is a line, so the question “what is the elevation along it?” is answered by sampling the raster at points along the geometry. Sample at an interval no larger than the cell size, or the line can step over whole cells, and treat the no-data code exactly as for polygons. The toy route below runs east across the row that holds the no-data block, sampled every 50 m, half the cell size.

Show code cell source

Hide code cell source

 
route = LineString([
    (X0, Y0 + 750),
    (X0 + 1000, Y0 + 750),
])

step = 50  # Half the 100 m cell size.
points = [
    route.interpolate(distance)
    for distance in np.arange(0, route.length, step)
]

coordinates = [(point.x, point.y) for point in points]
samples = np.array([
    value[0]
    for value in fine_src.sample(coordinates)
])

is_data = samples != fine_src.nodata

print(
    f"{len(samples)} samples, "
    f"{int((~is_data).sum())} fall on no-data cells"
)
print(
    "mean along the route (no-data masked):",
    round(float(samples[is_data].mean()), 3),
)
print(
    "mean if the no-data code were kept   :",
    round(float(samples.mean()), 1),
)

20 samples, 4 fall on no-data cells
mean along the route (no-data masked): 0.46
mean if the no-data code were kept   : -1999.4

Four samples land on the no-data block, and including them would turn the route’s value into a large negative number. The sampled values can also be summarized as a minimum, maximum, or change between consecutive samples when the question concerns a gradient.

4.7.10. Connection to network analysis#

A network edge is a vector feature, so a later network workflow can sample elevation, land cover, or another raster surface along its geometry and assign a documented cost. The same CRS, no-data, and resolution checks apply before using a raster-derived value in Chapter 5 network analysis.

4.7.11. Summary#

Vector–raster integration is an alignment and interpretation problem, not merely a file-conversion step. Match CRS and extent, choose the cell rule, resampling, and masking that fit the data type, preserve no-data information, and report the unit and sensitivity of every summary. A coverage ratio, a count of zero-valid-cell features, and a second resolution or masking rule turn those checks into evidence.
